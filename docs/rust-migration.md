# Rust 迁移进度

## 第一阶段：任务范围与准入（2026-11-17）

迁移范围固定为当前保留的任务，清单位于 `assets/task-catalog.json`。
包含刚恢复的阴阳寮任务；个人突破仍属于肝帝专属。
不迁移已移除的日常、每周任务，以及英杰试炼、寻找协作任务、花车巡游。
清单共 33 个入口（包括脚本设置、重启和全局游戏设置）。

`src/task_catalog.rs` 是 Rust 任务引擎的第一部分：加载编译进程序的任务清单，
转换兼容上游的配置键，并在参数查询、保存前检查任务准入。
`src/runtime.rs` 将 Rust 清单传给 Python 兼容执行器及其子任务。
Python 的菜单、调度过滤、回调和直接执行统一遵循该清单；不再维护另一份分类删除规则。
直接使用 Python 调试源码时读取同一份 JSON 清单。

本阶段已接入实际桌面运行路径，不是独立演示程序。
调度排序及具体任务流程仍由 Python 执行。
设备和识别的后续迁移情况见第二阶段，尚不能移除 Python 运行环境。

## 第二阶段：设备与识别主路径（2026-11-17）

`src/native.rs` 增加常驻 Rust 设备/识别执行器，通过同一个 EXE 的
`--native-worker` 入口运行，不引入额外 EXE 或 DLL 发布文件。
`bridge/native_backend.py` 把以下能力接入原 Python 任务的实际调用路径：

- Windows 窗口及桌面客户区 BitBlt 截图，原始输出为 RGB；
  桌面窗口恢复、摆放和尺寸适配继续复用原实现。
- 桌面消息按下、保持、抬起及捕获释放在 Rust 执行；Python 保持原来的
  悬停移动路径、坐标转换和随机按压时长。比较模式仅发送一次原 Python 点击。
- MuMu SDK 截图在 Rust 加载原模拟器 SDK、绑定对应实例并获取原始 RGBA 数据；
  Python 保留模拟器发现、原连接生命周期、图像翻转和通道适配。
  SDK 超时后结束阻塞的原生进程，读取操作由原有重试流程重新建立连接；
  输入结果不确定时停止，避免通过另一后端重复点击。
- ADB PNG 截图获取、点击、长按和滑动命令发送；PNG 解码仍由 Python/OpenCV 完成。
  显式指定设备序列号，原点击坐标、滑动轨迹生成及已有调用层的重试保持可用。
  HTTP 设备控制仍沿用原 Python 实现。
- 灰度/RGB 普通及二值遮罩模板匹配，使用逐通道去均值归一化相关系数，
  对齐 OpenCV `TM_CCOEFF_NORMED`，维持原阈值及 ROI 点击坐标。
  小范围直接计算，大范围使用 Rust FFT，返回完整评分图供原有规则消费。
- 本地 OCR 的文字检测及识别 ONNX 图通过 `tract-onnx` 在 Rust 推理，
  复用现有 PPOCR 模型和字典。CTC 解码、归一化/补零和最终检测框筛选已迁入 Rust；
  Python 保留缩放、轮廓/扩张及透视裁剪，
  保持原识别阈值与字符白名单。无需新的推理 DLL。
  每个原生进程最多缓存 4 种模型/输入尺寸的执行计划。
  本地 OCR 不再启动重复的 Python 推理服务；显式配置的远程 OCR 地址仍走原实现。

原 Python 源文件保持原样。默认使用上述 Rust 路径；开发时可以通过环境变量
`GANGAN_NATIVE_MODE=python` 使用 Python 对照版，`compare` 对照模板、OCR及截图、
以 Python 结果为准。比较模式不重复发送点击。

**尚未迁移**：scrcpy/minitouch、HTTP 设备控制、SIFT、模板缩放与候选筛选/NMS、
OCR 缩放、检测轮廓/扩张及透视裁剪、设备发现与窗口管理、调度排序及具体任务流程。
本阶段建立了可用于现有任务的 Rust 设备/识别执行路径，尚未宣称所有后端均完成迁移。
原始素材、模型和任务源码保留用于逐项对照，继续完善设备层后再逐个迁移具体任务。

验证：43 项 Rust 测试、128 项 Python 检查通过，其中包含 25 项原生集成测试。
覆盖随机及现有游戏画面、ROI 坐标、Python 适配调用、窗口截图、桌面消息顺序、
ADB 参数/PNG 传输、MuMu 实例绑定与超时重连、SDK 日志隔离。
OCR 验证覆盖 8/10/30 张券、批量文字识别、字符白名单、检测框与置信度，
并与原 ONNX Runtime 的输出张量对照。
测试使用隐藏的专用窗口和模拟 ADB/MuMu SDK，没有对用户的游戏发送测试点击。
实机对照时原 Python 连接 MuMu 实例 1 返回 RPC 1722，因此未完成真实设备长时间验收。

新增开发依赖经用户确认，Rust 依赖许可保存在 `licenses/Rust-dependencies.txt`。
本地源码构建需要 MinGW GCC 编译推理库的汇编内核，开发编译器放在
`.build-tools/w64devkit`，构建脚本也识别常见 MSYS2 编译器路径；用户运行预编译软件不需要它。

### 本轮续迁移：模板评分与 CTC 解码

`src/native/vision.rs` 提供完整模板评分矩阵。Python 兼容层只在 RuleImage 模块替换
对应的数值计算接口，普通、遮罩、多尺度、多目标和 NMS 前的评分统一进入 Rust；
缩放、阈值、ROI 更新及候选筛选继续执行原 Python 代码，原 OpenCV 模块不做全局替换。
浮点图像、浮点/多通道遮罩及其他匹配方法继续使用原接口。

FFT 使用平滑尺寸和两个实数序列打包，避免大图无谓扩展到更大的二次幂网格。
本机 1280×720 真实测试截图与 30×20 模板的完整评分图耗时约 110ms，
原 OpenCV 约 50ms；相同最高分和坐标已验证。这是一个固定样例，不代表所有规则耗时。
少量低对比背景与 OpenCV 存在约 0.002 的浮点差异，已用双精度直接公式复核 Rust 结果；
该样例高于 0.5 的候选评分误差小于 0.0001。

`src/native/ctc.rs` 执行 blank 移除、相邻重复折叠、字符白名单和置信度平均，
兼容空结果、批量结果和并列最大值。字典和白名单构造复用原定义。
Python 保留标签训练接口及非有限输入的原处理；实际 OCR 解码走 Rust。
测试覆盖重复数字被 blank 分隔、中文、空批次、空时间轴及实际券数识别。

为数值计算启用应用包的编译优化，依赖包仍使用原有体积优化；新 EXE 约 25MiB。

### 续迁移：OCR 输入与检测框筛选、匹配优化

`src/native/preprocess.rs` 实现识别输入的归一化、CHW 通道排列及右侧补零，
检测输入则使用现有均值/标准差归一化。0–255 全部像素值的输出已与 NumPy 逐项对照。
检测框的左右/上下排序、边界裁剪、整数截断及尺寸不超过 3 像素的框过滤也进入 Rust。
轮廓检测、扩张及透视裁剪仍由原实现负责。

`bridge/native_preprocess.py` 将这些能力接入实际 OCR 流程，继续复用原 OpenCV 缩放及其配置。
识别批次保留 NumPy 原有的长宽比排序、每批 6 张及输入顺序恢复。
缩放后的字节图像直接传给 Rust，在同一进程完成归一化、补零和 ONNX 推理；
相比原先发送 float32 输入，图像输入数据量减少至少 75%，归一化张量不再往返传输。
浮点图像及不适用的接口继续使用原 Python 处理路径。

模板评分继续使用双精度计算。小范围普通匹配改为积分统计复用和分组点积，
避免每个位置重复求和、平方和；遮罩保持原语义。FFT 每次变换复用行列临时空间，
并减少频域镜像索引中的除法计算。

同轮交替执行旧版/新版 EXE，64×44 搜索区与 60×40 RGB 模板的单次调用中位耗时
约 0.339ms → 0.277ms，减少约 18%；1280×720 真实截图与 30×20 模板约
112ms → 105ms，减少约 6%，仍慢于 OpenCV 的约 47ms。
这些数字包含原生进程通信，仅代表本机固定样例；不代表所有任务整体加速比例。

对照覆盖灰度/RGB 点积尾部、低对比模板与近乎纯色窗口、大图边缘坐标、
检测框排列/裁剪/空结果，以及跨批次、混合长宽比的文字和置信度。
原 Python 实现继续保留，本轮未新增依赖、修改 README 或改变具体任务流程。

## 后续迁移顺序

1. 设备、截图与识别接口，保持现有图片、识别规则和配置格式兼容。
2. 逐个替换清单内的任务流程，每个任务独立验证后再切换执行器。
3. 替换剩余 Python 调度、配置和执行能力后，移除 Python 运行环境。

迁移期间保留 Python 实现用于行为对照。上游更新先比较变更，
已移植部分更新对应 Rust 实现，未移植部分继续更新 Python 实现。
上游新增任务不会自动进入清单，必须明确决定支持范围并适配。
本阶段未同步上游或改变现有游戏操作逻辑。

## 验证

- Rust 测试覆盖任务范围、个人突破归属、移除及未知任务准入、配置键兼容。
- 桌面协议测试覆盖所有保留任务的参数读取、阴阳寮配置保存与调度、绘卷联动。
- `GanganMouse.exe --task-catalog` 输出当前二进制内的任务清单，无需启动 Python 或界面。
- `GanganMouse.exe --check` 验证实际 Rust 主程序与 Python 兼容执行器的连接。
- 新 EXE 构建后设置 `GANGAN_TEST_NATIVE` 为它的绝对路径，运行
  `python -m unittest discover -s tests -p test_native_backend.py -v` 验证原生执行器；
  使用 `test_native_ocr.py` 验证原生 OCR。
